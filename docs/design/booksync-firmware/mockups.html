The screens around reading

Static review gallery for plan groups B1–B5: connections, upgrade safety, updates, device controls and recovery. Every state is shown on X4 Pro touch, X4 Classic buttons and X3 text. Approved by the maintainer on 27 Nov 2026 (PR #202), with the change: “On screen keyboard should always be on the bottom for touch”. B2’s slim upgrade revision (2026-11-27) NEEDS APPROVAL; all other gallery groups are unchanged and retain approval. Implementation remains subject to plan slice dependencies.

Uses revision 16’s grayscale screen, 480 × 800 design viewport, serif headings, outlined rows, rounded actions and visible button focus. X3 keeps bounded text and numbered navigation; hardware capabilities are explicit. Frames follow the approved Home prototype. All content is synthetic; no external fonts, scripts, network or accounts.

All captions name the owning Library service: these are proposed value/intent groups, not frozen method names. UI renders immutable Library snapshots and sends intents only. Services own network, files, verification, persistence and hardware. A finished job never opens a screen, book or stale view.

Reading gate: unsolicited news, errors, progress, restarts and installation wait until no book is in the foreground. Dictionary/search and a connection-refused panel are user-opened in-book actions; Back preserves the exact reading position. The approved position prompt and end-of-book sheet are unchanged. No diagnostic upload, automatic reset or forced reconnect.

B2 · Slim upgrade and saved changes NEEDS APPROVAL · 2026-11-27

The slim upgrade notice replaces the former reading/settings/queue import and migration-recovery screens. Existing saved-change capacity, settings-reset and downgrade views below remain as drawn; they describe normal 0.12 operation, not legacy queue import. Only credentials, Wi-Fi and Tailnet identity activate from 0.11. No originals or native reader files are deleted. The last 0.11 bridge drains pending work before offering 0.12 (or allows the offer when signed out); F31 already routes old → bridge → 0.12.

Once only after a 0.11 upgrade, at Home with no book open. Either action durably dismisses the notice; reboot cannot show it again. “Later” keeps saved books available and leaves restoration to normal sync. “Sync from BookOrbit now” sends a Library intent for the normal F16 catalog / F18 lifecycle; match-by-identity reuses existing SD files where possible. Data absent from BookOrbit cannot come back from that sync; originals stay on the card. The approved B5 Home-news scene is unchanged; for 0.11 upgrades this B2 notice supplies the carry-over explanation and avoids duplicate upgrade notices.

Q1–Q7 are coordinator calls; the maintainer approved the mockups after seeing them on 27 Nov 2026.

Q1 · Pairing on button readers. Keep the existing QR, live link and manual Check; no phone-assisted handoff.

Q2 · Queue at capacity. Read-only saved-books path at capacity; operations that can't record durably are blocked with a message; never evict unacknowledged work.

Q3 · Retained imports (slim revision, 2026-11-27). Only credentials/Wi-Fi and Tailnet identity activate. Preserve unreadable originals; no reading-record or queue replay on 0.12. The B2 revision needs approval.

Q4 · Reset and forgotten code. Approve settings-only reset, one-boot basic settings and a separate verified forgot-code recovery; nothing erases books or sign-ins.

Q5 · Rollback admission. Offer Return to previous only for versions proven compatible after F29/F32; otherwise show Previous version unavailable.

Q6 · Diagnostic scope and retention. Local redacted export to SD, keep the last 5 reports, user can delete them; X3 gets a bounded summary.

Q7 · First-run and upgrade news. Optional first-run setup; once-only upgrade news on Home.
